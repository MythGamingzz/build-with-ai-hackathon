Cadence — App Map

A private, local experiment for comparing estimated sung words and chords with a hand-checked reference.

Privacy: recordings, transcript, reference annotations, and generated reports can contain private or copyrighted material. Keep them local and out of public commits. This guide contains no sample recording or transcript.

How the pieces fit

The command-line entry point checks the recording and optional reference, calls the local transcription and chord estimators, then saves predictions. When a reference is supplied, comparison results are rendered into a separate HTML report; the reference never replaces the predictions.

Reference route: follow one report run

This route is prepared for a source tour; it is not a record that someone has already completed the tour.

  1. src/cadence/cli.py — main: accepts the WAV and options, checks the input, then invokes local transcription and chord estimation. With --reference, it loads the annotations before running analysis.
  2. src/cadence/comparison.py — load_reference, compare_annotations, and build_report_html: validates reference timing, compares each labeled window with the raw estimate, and renders separate estimate/reference rows.
  3. tests/test_cli.py — test_keeps_raw_predictions_separate_from_reference_report: verifies a mismatch is visible in the report while the saved prediction stays unchanged. tests/test_comparison.py also checks matching/mismatching chord spans.

To change this, start here

  • Change which command options are accepted or how local files are written: src/cadence/cli.py, starting at build_parser and main.
  • Change annotation validation, span matching, or the match threshold: src/cadence/comparison.py, starting at load_reference and compare_annotations.
  • Change report labels or presentation: src/cadence/comparison.py, starting at build_report_html.
  • Change chord feature estimation: src/cadence/chords.py, starting at estimate_chords. Keep the known chord limitations visible in tests and comparisons.

A practice to reuse

Keep an estimate separate from the hand-checked answer. Here, the reference comparison exposes the chord misses without silently correcting model output; tests/test_cli.py verifies that separation. In another project, store an independent expected result and test the observable difference instead of changing generated output to look correct.

Run it again

From the project folder, run the local command with a recording and your own private reference:

.\.venv\Scripts\python.exe analyze.py <recording.wav> --language id --reference <private-reference.json> --output <private-output-folder>

The generated JSON and HTML report go to the selected output folder. Do not use real private paths or annotations in a public issue or commit.
